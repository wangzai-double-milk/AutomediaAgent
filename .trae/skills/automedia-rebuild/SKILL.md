# AutoMedia 改造与方法沉淀

1. 先读项目`README.md`、`docs/PROJECT_STRUCTURE.md`及相关功能矩阵项。按当前用户的明确授权执行，不将原作者的历史授权当作新实例权限。
2. 每个功能明确输入、原子动作、成功证据和失败恢复。先实现一条完整流程，再扩展批量；没有页面证据的功能标记未实测。
3. 模型测试不以成本为约束。调用真实模型验证文本、视觉、生成、编辑的协议与产物，密钥只由配置适配器读取，不输出或复制进文档。
4. 阅读外部原始仓库与许可证，提取有价值的小模块。在`docs/PROJECT_SOURCES.md`维护来源和许可证。不照搬庞大的平台合集，不因热度重写有效的Agent核心。
5. 检查 Git 已有改动；增量修改，不自动提交、推送、重置或清理用户文件。现有工作区长期存在大量暂存改动。
6. 平台实现放在 `automedia/behavior/platforms/`，`tools/`保留同模块兼容入口及动态工具发现协议；
   对应 handler 与 schema 必须同步；应用技能通过 `skills/registry.json` 注册。保持 Router → Workflow → Capability → Resource 的依赖方向。
7. 写操作用输入指纹防重复提交，记录账号、目标、执行前状态、结果和验证来源。提交结果不确定时读管理页核对；不要用重发来测试是否成功。
8. 浏览器恢复先查实际窗口、项目目录移动、扩展路径和桥接会话；发现管理策略或系统拦截时如实记录，不修改管理策略或绕过安全控制。
9. 用户要求复杂专业的方法说明，同时各技能松耦合。将可迁移经验写成短入口和详细引用；运行日志与具体样本留在任务中，长期原则留在个人技能。
10. 视频创作保留用户高节奏偏好：压缩移动和等待、提高反馈频率；替换素材时保持原参考动作节奏；故事板用简笔画和箭头表达轨迹。审片关注画风、动作逻辑与特效细节。
11. 接续时先核对当前任务与证据，仅推进未完成步骤；不重跑已通过测试，除非修改影响了它们。任务与具体账号记录保存在本机运行数据中，不加入公开文档。
12. 完成时汇报实际改变、验证范围、未完成环境前提与个人技能位置。未实测、仅规划或网页不支持的功能不能写成完成。
13. AXGroup增加后必须沿真实祖先消除标签重复；按钮文字可隔多层Group，不能只查一层parent。
    格式标签仅在包含四种发布类型的最小真实tab祖先内选择，避免侧栏同名项。
14. 实际话题需正文子节点“#词”与同父级“[话题]#”形成chip。添加前后比较plain_desc，
    等搜索候选真实浏览数出现再点击。系统输入事件要让Chrome完成处理，Cmd+Down定位末尾。
15. 区域读取等待业务控件与“数据加载中”消失；不要只因URL更新就报告成功。
    点击前再次核对站点与控件属性，用户/其他操作切换页面时停止当前动作。
16. 新账号平台测试与模型测试采用不同节奏。先完成共享提交额度、账号稳定ID绑定、
    默认暂停的后台队列和离线回归，再进行真实验收；工程间隔不是平台安全承诺。
    具体接续规则见[换号测试控制](../../../docs/NEW_ACCOUNT_TEST_CONTROL.md)，
    临时脚本和诊断输出放项目外，用户要求、最终代码与可复用方法留在当前项目。
17. 运营模型分支冻结同一账号快照；独立评审收到完整案例输入、原版本与分支产物。
    输出契约失败时保留原始产物和具体错误，不能只保存“校验失败”而丢失修正依据。
    取消必须传播到并行分支；重启恢复前先取得数据库单一所有者锁，避免误中断其他实例。
18. 人设与记忆界面属于本地工作流，不应被平台登录弹层拦截。
    合成模型与UI验收使用独立数据库；禁止把合成经历、示例定位或演示指标写入真实档案。
19. 人物形象使用独立人像提示与审图，不复用美食评分模板；保留生成来源、资产摘要与角色版本。
    生图期间人设变更时拒绝覆盖新版本，进程中断不自动重试供应商请求。
20. 最近记录从真实结果与明确的最终回答生成。受阻任务的最后一轮可能是工具片段，
    不能当最终手记；过滤内部标签，并将旧观察与本轮完整结果分开。图片文件格式以实际解码为准。
21. 区分直播预览与登录/账号限制。严格播放器验收保持停止；普通搜索可以从预览页进入已支持搜索，
    但须冻结允许动作、禁止误触next/feed/resume，且登录/验证码/限制依旧立即停止。
