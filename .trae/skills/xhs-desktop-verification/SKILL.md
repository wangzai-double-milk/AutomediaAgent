# 桌面验证方法

1. 先读取项目`README.md`和`docs/NEW_ACCOUNT_TEST_CONTROL.md`，确认当前用户的任务授权；
   每次恢复确认当前页面和未完成状态，不重新操作已经验收的测试作品。
2. 使用 `tools/xhs_read_desktop.py` 的精确可见链接读取推荐、搜索和用户主页。
   搜索链接点击后由网站填写正确来源；禁止手工拼接不匹配的 token/source。
3. 将详情限定在包含标题与评论输入框的最小真实祖先内。
   首页搜索框可能也是 TextArea；背景内容与详情内容不能合并。
4. 评论逐个按作者所属祖先分组。保留总数、已加载数、稳定ID是否可得；
   不将当前已加载评论称为全量，不从评论文字编造ID。
5. AX没有选择状态的控件才观察像素。截图限定实际小红书控件，
   激活浏览器并核对元素处于屏幕内；识别不明时停下，不能靠互动数量猜账号状态。
6. 点赞与收藏先读当前图标状态，再做一次提交，重新打开同一真实详情链接核对。
   图标动画可能替换AXImage；一次成功点击后不再点击，页面核对失败记录uncertain。
7. 关注动作同时绑定当前账号、笔记ID和真实作者ID；评论预填和清除绑定全文。
   写操作先原子落盘，再提交一次。不要用其他账号或无关联系人代替测试目标。
8. 核对不确定结果只读页面，将确认后的证据写回原操作记录并保留首次错误。
   可逆互动实测完成后恢复最初状态，禁止仅依据计数增加/减少宣布恢复。
9. 搜索筛选按真实分组找选项；可见选中色和返回结果分别留证据。
   AX树父子文本重复时按祖先消重，不用屏幕位置拼接不同卡片。
10. 页面功能与账号权限分别记录。没有权限、没有入口、未知字段和真正零值不同。
    查看[安装排障](../../../docs/installation_zh.md)和
    [能力矩阵](../../../docs/CAPABILITY_MATRIX.md)，先完成一条链路再扩展批量。
11. 草稿没有稳定ID，使用kind/title/saved_at精确绑定；真实列表共用一个容器，
    按相邻标题/日期/编辑/删除序列分段。删除弹层仅在与目标行绑定后确认一次；
    独立重开列表核对目标消失和其余条目保留，清理只动本次新建测试。
12. 指定回复用author_id+完整原文，核对编辑框“回复 昵称”与引用原文；
    重新打开详情核对同一线程中实际缩进回复，深层回复未验收时不能扩大成功范围。
13. 队列中断保留原spec、account、submitted_at和fingerprint，reconcile复用发布
    独立核对并限定实际note_id。仍只一次真实提交，不重跑整条发布链路。
14. 工作台真实输入发起只读任务，确认先读SOP再调用受闸门工具，并记录返回结果。
    Chrome无障碍树偶发缺失时观察焦点，关闭弹窗后恢复到输入框；不重复发送任务。
15. 新稿可以使用独立空标签保留旧编辑页；本次发布内固定创作中心标签并核对选中状态，
    不能靠同名标签猜目标。标签集合变化则停止。原生离开确认只可取消以保留内容，
    不为新发帖丢弃旧稿。发布后明确区分“已提交、仅自己可见”和“平台审核通过”。
