# xhs_roast_style · 毒舌语风规范

> 被 [`../xhs_review/SKILL.md`](../xhs_review/SKILL.md) §Step 4.5 / §Step 5b、未来的 publish_sop 引用。
> 风格已经写进 [`tools/image.py`](../tools/image.py) 的 `SYSTEM_PROMPT_WITH_REFS`，本文是**输出环节的格式规范 + 禁令**，不是 prompt 本身。

## 1. 调性原则

由模型在 `roast` 字段直接生成。要点：
- **30 字内一句**，点出最核心差距
- 让用户记住"要怎么改"
- **不要太礼貌**——这是用户明确要求的产品定位
- 必须包含**具体差距**（光线/构图/色调/主菜大小），不能是空话（"不太行"、"差点意思"）

## 2. 范例（用户确认过的调性）

### 跟爆款对比类
> 看看人家爆款大铜锅气势全开，你这小锅活像过家家。
> 爆款人家牛肉切片摆得整整齐齐，你这锅薄荷把主菜埋了，发悬疑剧呢？

### 单图诊断类
> 色调灰得像我工资条，对比爆款那个暖光油润，差出三个食欲值。
> 构图被字节 logo 抢戏，活像食堂监控偷拍流出。
> 这构图我妈都看不下去。
> 光线像在地下室拍的。
> 主菜呢？我得用放大镜找？
> 这色调像隔夜剩饭。
> 构图歪得能当压缩饼干。
> 你这图拍的太烂了，你看看人家怎么拍的。

## 3. 输出端格式禁令（review_sop §Step 5b 严格执行）

调用方在拼回复时**必须**：

1. **第 1 行就是 roast** —— 不许在前面加 "📌 核心问题"、"经过分析"、"您的图片..." 这种甲方话术
2. **原样复述 review.roast 字段** —— 不许"翻译"成更礼貌的版本（"或许可以考虑..."）
3. **不许在毒舌段落塞**：
   - "建议..."、"或许..."、"可以..."（软化词）
   - "哦"、"啦"、"呢"（萌系语气词）
   - emoji（毒舌不带 emoji 才有力度）
4. **review_sop §Step 4.5 PASS 路径**：roast 放在「🔥 审图毒舌点评」段落，**仍然原样复述**，不许因为 PASS 了就软化

## 5. 反例（曾经被用户骂回去的输出）

❌ 错误 1：开头被 emoji 标题盖住
```
📌 核心问题分析
您这张图存在以下几个可优化的地方：
1. 构图方面...
```
（毒舌完全消失，变成乙方汇报）

❌ 错误 2：把毒舌"翻译"成商务口吻
```
roast 原文：「这色调像隔夜剩饭」
被改写成：「色调略微偏冷，建议适当调整」
```
（语气彻底变软，失去产品定位）

❌ 错误 3：emoji + 软化
```
您的图片整体感觉还不错呢～就是色调有点冷哦😊 可以调暖一些哦～
```
（用户看到这种回复会**直接弃用 agent**——确凿事实）
