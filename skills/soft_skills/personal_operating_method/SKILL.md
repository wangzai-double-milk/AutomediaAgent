# 个人运营方法

这是方法资源，不调用工具、不选择工作流。原实例个人授权保留在本机
`USER_REQUIREMENTS.md`，不随源码分发；其他实例须以各自用户授权为准。

- 先获得可观察证据，再作选题判断；真实样本、模型分析、页面结果要能追溯。
- 模型质量与实测覆盖优先，成本不作为本项目减少验证的理由。
- 复杂专业的方法说明保留领域经验，各能力保持松耦合；只吸收外部项目需要的小模块。
- 视频节奏通过压缩移动/等待、提高动作与反馈频率形成，不能仅靠缩短总时长。
- 替换背景和角色时，保持原参考动作时间点、镜头节奏与反馈效果。
- 审片精确到画风、人物移动逻辑、动作轨迹、场面细节和特效，不凭标题猜画面。
- 故事板使用简笔画，箭头表示关键动作轨迹和剧情流转。
- 每轮运营保留：目标 → 样本 → 假设 → 制作选择 → 发布参数 → 真实结果 → 下一轮修正。
- 已获得的授权在对应实例与范围内持续有效，不为同一范围反复询问；源码中的方法不授予新实例账号操作权限。
- 个人方法与取舍长期保存；密钥、Cookie、具体任务流水不混进技能。
- 真实写操作采用“输入回读 → 操作前落盘 → 只提交一次 → 重新进入结果页核对”；
  成功提示只是一条证据，目标ID、账号、内容与可见性需独立核对。
- 结果超时或不明确先保留记录，再只读核对；禁止把重试写动作当验证手段。
  实验优先使用新建且说明用途的测试作品；实验清理保留原有作品。
- 浏览器观察需覆盖业务控件、系统确认框与真实焦点；页面占位计数、输入框内容
  和侧栏预览不能冒充最终业务数据或已经发送的消息。
- 对富文本、平台标签和上传等待保留独立验证：推荐候选点击后需真正话题标记，
  话题添加不能改变正文；多图每次增加都核对计数；富文本正常输入后按实际内容核对。
- 先等“加载中”消失再记录指标。权限可因区域不同而不同，粉丝数据可读不代表
  账号概览和内容分析也可读；实际0、缺失、没有权限三种状态不能混用。
- 模板排版的原文、最终笔记描述与图片分别记录；原文核对不代表所有生成图片像素正确。
  音频先核对实际时长，再验证网页音频和封面上传，不靠文件后缀猜有效性。
- 链接携带真实来源与临时访问参数，跟随可见链接并让网站完成跳转；不编造缺失来源。
  详情、评论、卡片都按实际祖先限定，背景列表与详情内容分别处理。
- 已加载评论数量不代表全量。点赞/收藏的真实选中状态与全站计数变化不同；
  图标动画造成观察失败时只读恢复，不重复点击；可逆实验恢复起始状态后留独立证据。
- 网站输入值和编辑模式分开核对：真实点击展开、正常输入事件、发送按钮可用之后才提交。
  无话题正文、作者徽标和背景列表按各自容器处理，禁止以整页文字冒充目标正文。
- 定时验证用已保存作品的开关与日期；卡片异步从创建时间切换定时时间，
  不从早期占位显示否定已保存时间。测试任务提前清理并独立确认未来队列没有残留。
- 缺稳定ID时只用实际可观察的复合身份：草稿用类型/标题/保存时间；
  评论用真实作者ID/原文；不能将昵称、列表序号或自造hash当平台ID。
- 恢复队列用持久化原规格、账号、提交时间和实际作品ID做独立核对，
  不重新上传媒体或重新提交。对临时素材不存在与定时已过去，允许只读恢复原记录。
- 回复先核对引用原文，再验证目标原评论所属线程的缩进回复；相同文字出现在
  其他评论位置不构成回复成功。缺数据或有歧义停止，不放宽成作者名匹配。
- 表单预填、提交成功提示与服务器最终结果分别记录。合集和RSS缺独立结果证明时
  不称创建/导入完成；缺真实订阅地址、账号权限和邮箱验证码时保留具体缺项。
- 工作台验收同时覆盖实际界面与工具结果；关闭弹窗后恢复输入焦点，
  避免隐藏控件持有焦点。浏览器扩展未连接与系统桌面可用分开表达。
- 已保存草稿直接恢复最终编辑器后提交，避免重复上传或再次排版；
  平台可能在发布后自动移除本地草稿，应记录前后数量和被消耗的测试目标。
- 平台创建页与已发布编辑页控件可能不同。定时开关不存在时不伪造disabled状态；
  结合立即发布时间与管理卡片非定时做有限核对，仍不声称不存在的开关已读。
- 合集封面经过平台裁剪确认，列表/编辑回读与媒体像素检验分别表述。
  对没有稳定ID的合集，用唯一名称+简介绑定；多目标共容器时歧义必须先解决。
- 实测授权持续有效，实际平台限制仍是新的执行前提。出现账号风险原文时停止写操作，
  保留已经提交的结果，继续本地改造；不靠改账号昵称、换模型或换浏览器通路解决限制。
- 普通合集名称与草稿绑定可通过保存重开核对；简介没有独立读取入口时单独标明。
  发布前副作用如保存草稿应在工具说明中表达；平台没有的改名/删除控件不能猜测。
- 背景队列只在任务到期后选择已有创作中心标签；未来任务与状态轮询不抢浏览器焦点。
- 换账号测试先完成本地共享额度与绑定控制，随后核对真实健康主页稳定ID和创作中心昵称。
  新账号健康观察不覆盖旧账号限制；任务与本地草稿不因昵称变化而转移归属。
- 测试频率按全局提交间隔和单账号滚动额度保存，进程重启、任务切换和结果超时都不能重置。
  达到额度立即返回下次时间并停止当前执行，不长时间等待；30分钟间隔不构成平台安全保证。
  模型接口充分离线测试与平台实验频率分开安排，不因为模型不计成本而连续影响真实账号。
- 多步骤流程中的保存草稿也占提交额度；创建合集后的保存重开应分阶段完成。
  零提交拒绝必须发生在操作journal之前，保留原任务与页面，不伪装成已提交的不确定结果。
  完整方法见[换号测试控制](../../../docs/NEW_ACCOUNT_TEST_CONTROL.md)。
