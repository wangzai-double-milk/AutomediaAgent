# 陌生环境探索引擎（Explore & World-Modeling）

> **当 Agent 落到一个还不熟的平台时（没有专用工具、`memory/world_model/<platform>.md` 也没有），走这里。**
> 像人第一次用一个新 App：不去读它的 API，而是**扫一眼→猜→试→看反应→在心里建立"这个平台怎么用"的地图→熟了之后闭眼操作→把反复成功的流程固化**。
> 本引擎依赖 [`../perception_action/SKILL.md`](../perception_action/SKILL.md)（眼睛+手）执行每一步动作。

## 何时进来
- 用户要在一个**没有专用方言**的平台做事（不是小红书）。
- 有平台但 `memory/world_model/<platform>.md` 不存在或很薄 → 边做边补。
- 用户显式说"去研究下这个 App/网站怎么用"。
- 任何模式（研究/运营）落到陌生平台需要操作时，由它们借道进来。

## 探索循环（O-H-P-O-M-E-C）

```
① Orient 定向    我在什么平台/什么页面？整体长啥样、能干什么？
                 → web_learn_page() 认页面 + web_scan 读文本；先建立"我在哪"
② Hypothesize 假设  结合当前目标 → "要达成 X，我应该点哪/找什么/分几步"
                    → 写不出假设 = 缺方法 → 走渠道经纪层先查"别人在这平台怎么做X"
③ Probe 试探     用 web_visual_click / web_visual_fill 动一下（最小可逆的一步）
④ Observe 观察   页面变了没？变成了什么？符合假设吗？(看 verified + 再 scan/learn 一次)
⑤ Model 建模    把"这个平台·这种页·这个元素·这个后果"写进世界模型(见下)。
                假设错 → 修正模型，回 ②
⑥ Exploit 利用   模型够确定后，按沉淀的步骤直接做（元素已结晶进 selector 缓存，免视觉）
⑦ Crystallize 结晶  一段反复成功的完整流程 → 固化成世界模型条目 / 平台 SOP / 工具(L3)
        └─ 模型/缓存失效（平台改版） → 退回 ① 重新探索（自愈）
```

要点：
- **每次只试最小、最可逆的一步**，看清反应再走下一步——别一次点一串不可逆操作。
- **不可逆操作（发布/删除/付款/关注真人）在探索期一律先停下确认**，别拿用户账号做破坏性试探。
- 试探卡住（连续失败/找不到入口）→ **不是硬试**，去渠道经纪层查"这个平台怎么做这件事"，或 `ask_user`（RULES：3 次失败请求介入）。

## 世界模型：探索的产物（L2 沉淀）

每个平台维护一份 `memory/world_model/<platform>.md`（首次探索时创建，用 `file_write`；持续探索时用 `file_patch` 增量补）。建议结构：

```markdown
# <platform> 世界模型 (last_updated: <date>)
## 一句话画像
这个平台是什么、擅长承载什么内容、主要用户是谁。
## 关键页面地图
- 首页/推荐流：URL 形态、布局、能干什么
- 搜索：搜索框在哪、结果页结构、有哪些筛选
- 内容详情：正文/评论/互动按钮的位置与加载方式
- 创作/发布：入口在哪、几步、有什么坑（如必须先存草稿）
- 个人/数据中心：粉丝/播放/互动数据在哪看
## 已验证的操作流程（可直接复用）
- 「发一条内容」：第1步…第2步…（哪些元素已结晶进缓存）
- 「抓一条内容的正文+评论」：…
## 平台机制与信号
- 推荐/流量机制（如完播率、互动率），爆款信号长什么样
- 风控红线、发布规则、token/登录注意事项
## 已知坑 / 失败记录
- 什么操作会失败、改版导致哪些 selector 失效过
```

> 世界模型 = Agent 对这个平台的"心智地图"。**它越完整，下次在这个平台就越像老手。** 这正是"像人一样越用越熟"的载体。

## 从探索到方言（L2 → L3 的进阶）
当某平台的世界模型足够成熟、某些流程高频又稳定：
- 把该平台的操作 SOP 单独立成 `skills/hard_skills/<platform>_*/SKILL.md`（参考小红书 `xhs_*`）。
- 把高频读数据/操作结晶成专用工具（`create_skill` 或脚本），从"每次视觉操作"升级为"确定性快路径"。
- **小红书 `xhs_*` 就是这条路走到头的样板**：它本质是"在小红书上探索熟练后结晶出的方言"。

## 纪律

### 🔴 六条硬约束（不满足 = 任务未完成，不许收尾）

**1. 探索广度——必须踩完主要功能区，别浅尝辄止。**
"研究这个平台怎么用"绝不是"搜一个词、点开一个内容看看"就算完。第一次进一个陌生平台，必须像新用户一样**把主要功能区挨个点一遍、各看一眼记一笔**，至少覆盖：
- **全局导航**：顶/底/侧栏每一个入口（首页/推荐、关注、发现、搜索、发布/创作中心、消息/通知、我的）都点进去看一眼它长啥样、能干什么。
- **消息/私信**：点进消息与私信列表，看清楚结构（通知、评论、私信分别在哪、能不能回复），这是运营的核心通道，必须摸清。
- **个人主页**：进自己主页，看清粉丝/作品/数据/设置入口在哪。
- **内容详情**：随便点开一条内容，看正文/评论/互动按钮的位置和加载方式。
- **创作/发布入口**：找到"发内容"在哪、点进去看是几步、有什么前置。

> 每到一个功能区，**点一下→观察→记一笔到世界模型**，不要点完就忘。覆盖不全就别说"探索完了"。

**2. 探索深度——核心交互必须亲手跑通一次，不能只"看界面"。**
光看页面长什么样 ≠ 学会用。要真正掌握一个平台，**必须亲手把核心交互各完整跑通至少一次、用页面反馈自证成功**，而不是只看入口在哪。核心交互至少包括：
- **发一条内容**：真的走完"创作→填标题正文/选图→发布"，发布成功后立刻**自己删掉**（测试内容用明显的占位文案如"测试 test 请忽略"，发完即删，不留痕）。
- **评论一条**：在某条内容下真的发一条评论，看到它出现在评论区，然后**自己删掉**。
- **回一条私信/互动**：进私信或评论区，真的回复一条（无真实对象就给自己/测试号发），确认发送成功后清理。
- 其它高频动作（点赞/收藏/关注）也各试一次并撤销，确认按钮反馈与状态变化。

> **判定标准**：每个核心交互都要拿到"操作前→操作后"页面发生预期变化的证据（如评论真的出现了、作品列表多了一条），并把"这条流程怎么走通的、哪几步、踩了什么坑"写进世界模型「已验证的操作流程」。**没亲手跑通核心交互 = 没学会 = 任务未完成。** 严禁只描述"发布按钮在左上角"就当掌握了发布。

**3. 强制沉淀——探索结束必须落地世界模型，否则任务不算完成。**
本次探索结束前，**必须**用 `file_write`/`file_patch` 写出/更新 `memory/world_model/<平台>.md`（结构见上文），把这次踩点的每个功能区、页面地图、**亲手验证过的操作流程（含发/评论/回私信的具体步骤）**、平台机制、踩的坑都写进去。**没产出世界模型文件 = 任务失败**，不许只在对话里口头总结就收尾。
- **沉淀技能的落点固定**：要把可复用的内容/打法 SOP 结晶成技能时，**一律写到 `skills/soft_skills/<技能名>/SKILL.md`**（用 `create_skill`）。**绝对禁止**自创 `skills/local/` 或其它目录——只有 `skills/soft_skills/` 下的技能才会被加载。

**4. 禁止闭眼编——视觉没抓到真实内容，绝不能用模型自有知识凑。**
做研究/调研类探索时，结论只能来自**这次真实抓到的页面内容**。当前关键词/入口找不到目标内容时：
- 先**换关键词、换入口、换筛选条件、多滚几屏**重试（至少换 2 种思路）。
- 仍抓不到，就**如实告诉用户"在该平台没检索到符合的内容"**，并说明试过哪些路径。
- **严禁**凭模型训练知识编造一份看起来很完整的报告——抓不到就是抓不到，假装看到过是最严重的错误。

**5. 视频内容必须真"看"——禁止只读标题/点赞数脑补。**
在以视频为主的平台（抖音/B站/视频号等）研究或建模内容时，**对要下结论的视频，必须调用通用内容理解工具（`analyze_media`，平台无关，底层走 Files API 整段上传理解）真正看完整段视频**，再根据画面/口播/节奏得出结论。
- **严禁**只读视频卡片的标题、`#话题`、点赞数、评论文字就总结"这个视频讲了什么、为什么火"——那是闭眼编的变种。
- 判定标准：凡是报告里出现"某视频内容如何/拍法如何/爆款公式如何"的结论，必须有对应的一次视频理解调用作支撑（trace 里能看到 `vlm_analyze` 记录、`logs/image.log` 里能看到 `/files` 上传或 `input_video` 调用）。
- **怎么把视频喂给 `analyze_media`**（任意平台通用思路，先进到视频详情页再抠真实流地址）：
  1. 用 `web_execute_js` 在详情页执行 `document.querySelector('video')?.src` 取 `<video>` 的 src；抖音常是 `blob:` 开头不能直传，则改取 `video.currentSrc`、或翻页面 JSON（抖音在 `window._ROUTER_DATA` / `__INIT_PROPS__` 里有 `playApi`/`play_addr.url_list`，B站在 `window.__playinfo__`）。
  2. 拿到形如 `https://....mp4` 或 `.m3u8` 的真实地址后，调 `analyze_media({video_url: "<地址>", prompt: "看完整段视频，告诉我..."})`。
  3. 实在抠不到可下载的流地址（纯 blob/加密），就如实说"未能拉到该平台视频流"，不要用标题硬凑。
  4. 把"这个平台视频 url 在哪个字段/怎么抠"的成功经验写进世界模型，下次直接复用。
- 取不到视频流地址或上传失败时，如实说明"未能拉到视频内容"，不要用标题硬凑。

**6. 禁止虚报动作结果——动作成没成以工具返回为准。**
点赞/关注/评论/发布等动作，**是否成功必须以工具返回的 `verified`/`ok`/`state` 字段为准**，不能凭"我点了一下"就当成功。
- 交付清单/报告里标"✅已关注/已点赞"前，**必须确认对应动作 trace 是 `ok:true` 且 `verified:true`**。
- 动作 `ok:false` 或 `verified:false` 时：先换 `xhs` 带验证的专用动作或重试，仍失败就**如实列入"未完成"**，**严禁标成已完成**——动作没成却报成功，和闭眼编一样严重。

### 其它纪律
7. **可逆即测、不可逆才停**：探索期鼓励用"测完即删/可撤销"的方式亲手验证核心交互（发→删、评论→删、关注→取关）；只有**真正不可逆或会打扰真人的操作**（付款、给陌生真人发骚扰私信、删除用户已有的真实作品/数据）才必须先停下确认。测试动作务必用明显占位内容并在验证后立即清理，绝不留下垃圾。
8. 卡住先查（渠道经纪层）不硬试；3 次失败请求用户介入。
9. **跑通就沉淀**：每段成功流程都要写回世界模型，越完整下次越像老手。
10. 探索产出的事实/机制结论要可追溯（来自哪次试探/哪篇参考）。
