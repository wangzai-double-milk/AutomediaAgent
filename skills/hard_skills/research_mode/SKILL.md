# 模式 A · 研究模式（消费信息 → 出文档）

> 由 [`../agent_core/SKILL.md`](../agent_core/SKILL.md) 冷启动判定为 **A 类**后进入。
> 本模式只**消费/总结**信息，**产出是一份文档**，**不发帖、不动账号**。
> **平台无关**：下文以小红书方言工具举例，但研究可来自任意渠道——该去哪几个平台读、怎么读，交给[渠道经纪层](../../soft_skills/search_anywhere/SKILL.md) 决定。没有方言工具的平台（知乎/B站/抖音…）借道 [`../explore_mode/SKILL.md`](../explore_mode/SKILL.md) 视觉抓取。
> 任何一步"不知道怎么做/信息不够" → 触发[渠道经纪层](../../soft_skills/search_anywhere/SKILL.md)。

## 何时进入
用户想"找信息/做功课/要个总结"，例如：
- "我想知道怎么健身 / 新手减脂怎么吃"
- "大家都怎么拍 ootd / 探店笔记怎么写"
- "帮我调研下『露营』这个赛道现在什么内容火"

## 流程（6 步）

### Step 1 — 明确研究主题 + 范围
- 从用户原话提炼**主题**和**关注点**（如主题=健身，关注点=新手/在家/无器械）。
- **能从原话推断就别问**。只有主题实在太模糊（如"帮我查点东西"）才用 `ask_user` 问一句。
- 先建工作区：`xhs_task_init(user_request=...)` 拿到 `task_dir`。
- 把主题拆成 1~3 个**检索关键词**（站内搜索一次只吃一个 keyword）。

### Step 2 — 选定渠道并抓取 Top-N 高赞内容
- **先选渠道**（见[渠道经纪层](../../soft_skills/search_anywhere/SKILL.md)）：主题适合哪个平台？生活种草→小红书；深度原理→知乎；教程测评→B站。可并行多个。
- **视频原生任务必须覆盖视频平台**：如果用户研究的是**短剧、短视频、拍摄风格、剪辑节奏、口播、镜头语言、爆款视频、别人怎么拍/怎么说**，则小红书图文和 Google 行业文章只能作为辅助，**必须至少进入一个视频原生平台**（优先抖音，其次 B站/快手/视频号）搜索并点开代表视频。不能因为小红书结果“看起来够多”就跳过视频平台。
- **小红书（已有方言，最快）**：用 `xhs_search_viral(keyword, top_n=10, fetch_content=5)` 抓爆款封面 + 前 N 篇正文。
  - `top_n` 控制看多少封面，`fetch_content` 控制真正点进去抓正文+多图+评论的篇数。
  - 多个关键词就多调几次。需要更精准的筛选（最新/最多点赞/图文/一周内）可改用 `xhs_search_feeds(keyword, filters=...)` 再 `xhs_get_feed_detail` 逐条取详情。
  - 结果已落盘到 `task_dir/viral_refs/`（封面 + 多图 + `viral_meta.json`）。
- **其它平台（无方言）**：借道 [`../explore_mode/SKILL.md`](../explore_mode/SKILL.md) + [`../perception_action/SKILL.md`](../perception_action/SKILL.md)，像人一样打开它的搜索、读结果，把要点落盘到 `task_dir`。

### Step 3 — 逐篇深读（正文 + 图内文字 + 高赞评论 + 视频整段）
- `viral_meta.json` 里每篇的 `content` 含 `desc`（正文）、`image_texts`（**图内 OCR，攻略经常藏这**）、`comments`（评论区，干货/避坑也常在这）。
- 攻略型笔记的关键信息**大概率在图里不在正文** → 一定要读 `image_texts`。
- 单张图缺 OCR 时用 `xhs.extract_text_from_image(path)` 补抓。
- 评论区高赞回复要重点看（真实反馈、补充、踩坑）。
- **视频内容必须真看**：研究的内容是视频（抖音/B站/视频号，或小红书视频笔记）时，**对要下结论的视频必须调用 `analyze_media`（通用内容理解工具，平台无关，底层走 Files API 整段上传理解）看完整段视频**，再依据画面/口播/节奏总结。**严禁只读标题、`#话题`、点赞数、评论就断言"这个视频讲了什么/为什么火"**——那等于闭眼编。拉不到视频流就如实说明，不要用标题硬凑。
- **视频样本数门槛**：凡报告要总结“拍摄风格/剪辑节奏/镜头语言/观众爱看什么视频/爆款视频公式”，至少真看 **3 条代表视频**（不足 3 条就写明只看了几条、为什么不足），每条都要在报告的信息来源里标出平台、标题/作者、链接或页面线索、是否已 `analyze_media`。

### Step 4 — 去重、归纳、交叉验证
- 把多篇里**反复出现**的观点视为高可信共识；**只有 1 篇提**的存疑，标注"少数说法"。
- 互相矛盾的点 → 不要直接采信。**触发搜索贯穿**：用技能库/网络搜索补充权威信息再下结论（见 §搜索贯穿）。
- 严禁凭空编：文档里每条结论都应能追溯到某篇笔记/某次搜索。

### Step 5 — 产出结构化文档
- 写报告前先做**证据门禁**：
  - 若任务属于视频原生研究，但没有进入任何视频平台搜索：**不得写最终报告**，先去抖音/B站/快手/视频号补搜。
  - 若报告里会出现视频内容/拍法/剪辑结论，但 `logs/image.log` 或 trace 里没有对应 `analyze_media` / `/files` / `input_video` 证据：**不得写最终报告**，先补看视频；实在拉不到视频流，报告必须把该结论降级为“来自图文/行业资料推测”，不能写成实测结论。
- 用 `file_write` 写到 `task_dir/research_report.md`，结构建议：
  1. **结论速览**（3~5 条要点，用户最忙时只看这段）
  2. **分主题展开**（每个子主题：共识做法 + 注意事项 + 出处笔记标题/链接）
  3. **避坑 / 少数派说法**（标注可信度）
  4. **信息来源清单**（笔记标题 + note_url + 点赞数，体现热度）
- 文末附"本次共看了 N 篇笔记 + M 次外部搜索"，让用户知道覆盖面。
- 把报告路径回报给用户。

### Step 6 — 沉淀用户偏好
- 用 `update_user_preference(category="interest", content="关注X主题/Y方向")` 记下用户这次关心什么。
- 下次该用户再来，`xhs_main` 冷启动会自动读回，能更快对上需求。

## 搜索贯穿（本模式高频）
研究模式经常需要补外部信息，按优先级走三通道（详见 [`../../soft_skills/search_anywhere/SKILL.md`](../../soft_skills/search_anywhere/SKILL.md)）：
1. **站内** `xhs_search_viral` —— 看同行/真实用户怎么说（本模式主力）。
2. **技能库** `memory/skill_search/` —— "某件事怎么做"的方法论（英文 query）。
3. **网络** `web_scan`+`web_execute_js` 开 Google —— 站内说法矛盾/需要权威佐证时兜底。

## 纪律
1. **默认只读；但用户明确要求互动时，可顺手互动。**
   - **默认**：研究模式以"消费信息、产出文档"为主，不主动发帖/点赞/关注/评论。
   - **例外（重要）**：当用户的指令里**明确带了互动诉求**（如"好的就点赞关注""帮我关注几个优质博主""遇到喜欢的点个赞"），就**必须在研究过程中顺手完成这些互动**——读到/看完一个你判断优质的内容后，立刻调用对应动作（小红书用 `xhs_interact` 等方言工具；抖音/B站等无方言平台用 `web_visual_click` 点页面上的关注/点赞按钮）。**别因为"我在研究模式"就把用户白纸黑字要的关注/点赞给跳过——那是没完成任务。**
   - 互动同样遵守[全局纪律](../agent_core/SKILL.md)：动作成没成以工具返回的 `verified`/`ok` 为准，失败要重试或如实报"未完成"，**严禁虚报"已关注/已点赞"**。
   - 若用户**完全没提**互动、只要总结，则保持纯只读。
2. **🔴 禁止闭眼编（最高优先级）**：报告里每一条结论都必须能追溯到**这次真实抓到的**某篇笔记/某次搜索，**严禁用模型自有训练知识凑一份看起来完整的报告**。
   - 在某平台（尤其是借道 explore 视觉抓取的抖音/B站/知乎等）没检索到目标内容时，先**换关键词、换入口、换筛选、多滚几屏**至少试 2 种思路。
   - 仍抓不到，就**如实写"在该平台未检索到符合的内容"**并说明试过哪些路径，宁可报告短、宁可承认没找到，也不许编。
   - **视频结论必须真看过整段**：任何关于"某视频内容/拍法/爆款公式"的结论，都必须有一次 `analyze_media` 视频理解调用作支撑（`logs/image.log` 能看到 `/files` 上传或 `input_video` 调用）。只凭标题/点赞数/评论臆测视频内容，等同闭眼编。
   - 假装看到过、把常识当调研结果，是本模式最严重的错误。
3. **够用即止，但不能绕过必备证据**：覆盖到能回答用户问题就出文档，不要无限刷帖；但“够用”必须先满足本模式的硬门槛。视频原生任务没有视频平台样本、视频内容结论没有 `analyze_media` 证据、用户明确要求互动但没执行互动，都不算够用。
4. 文件用绝对路径（`task_dir` 下）。
5. **沉淀技能只能进 `skills/soft_skills/`**：要把调研沉淀成可复用 SOP 技能时，用 `create_skill` 写到 `skills/soft_skills/<技能名>/SKILL.md`。**绝对禁止**自创 `skills/local/` 或其它目录——只有 `skills/soft_skills/` 下的技能才会被加载。
