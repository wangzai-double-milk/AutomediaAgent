# Research Workflow

目标是回答问题并形成报告，不主动改变账号状态。依赖见 `skills/registry.json`。

## 流程

1. **建立任务**：调用 `xhs_task_init`，把主题拆成首轮 1~3 个问题。
2. **选择渠道**：生活与消费优先小红书，视频表达必须覆盖抖音/B站等视频平台；权威事实补官方或网络来源。
3. **小批搜索**：每轮 3~5 个候选，不一次囤积大量标题。
4. **逐条深读**：
   - 读取正文、评论和元数据。
   - 图片结论必须调用 `analyze_media` 看图。
   - 视频内容/节奏结论必须调用 `analyze_media` 看真实视频。
5. **滚动写报告**：第一批证据出现后立即创建 `research_report.md`；以后每轮先去重和修正，再写新增知识。
6. **继续搜索**：根据报告缺口改变关键词或平台。达到代码收敛门禁后才能结束。
7. **交付**：报告按主题组织，包含结论速览、证据、争议/限制和来源清单。

## 跨平台执行

- 小红书：`xhs_search` capability。
- 抖音：`douyin_browse` capability；视频理解仍用 `analyze_media`，成功后记录研究增量。
- 未提供专用能力的平台：`explore_mode` + `perception_action`。
- 需要渠道建议：`search_anywhere`。

用户点名多个平台时，每个平台都必须在本轮真实访问，旧报告只能作为旁证。

## 边界

- 不调用发布工作流。
- 用户未要求时不点赞、关注或评论。
- 用户明确要求互动时，可调用对应平台 capability，但动作必须验证成功。
- 不把来源名称当章节标题；多个来源的相同观点合并为共识。
- 抓不到内容就记录尝试和限制，不用模型常识伪装成调研结果。
