# 感知-动作引擎（Perception-Action Engine）

> **这是 Agent 操作任何页面的"眼睛 + 手"。** 它让 Agent 的能力边界等于"一个人盯着浏览器能做的一切"，而不是"我们写了多少个工具"。
> 任何平台**没有专用工具**、或**专用工具失败**（改版/token失效/选择器找不到）时，**都退到这里像人一样操作**——所以 Agent 永远不会真正卡死。

## 核心理念：感知优先，工具是结晶缓存

- 默认相信：**只要能看屏幕 + 能动鼠标键盘，就能搞定任何平台**，跟人一样。
- 写死的 selector / 专用读数据工具（如 `xhs_*`）是**走熟了的快路径**，不是能力来源。它们快、省、准，但会随平台改版失效。
- 失效不可怕：**退回视觉感知，重新看着试一次**，并把新学到的固化下来（见"自学习/结晶"）。

## 三个原子能力（GA 已注册）

| 工具 | 作用 | 关键点 |
|---|---|---|
| `web_learn_page(url_hint?)` | 截图当前页 → VLM 一次性认出主要可交互元素 → 入缓存 | **只建索引，不执行任何操作**。进新页/新站先做一次，之后同站点 `visual_click/fill` 可走 fast path 免 VLM |
| `web_visual_click(target_desc)` | 截图 → VLM 定位 `target_desc` 描述的元素 → CDP 物理点击 | 用**自然语言**描述目标（如"右上角的发布按钮""第三张卡片"）。返回 `verified` 表示点击后页面真的变了 |
| `web_visual_fill(target_desc, text)` | 截图 → VLM 找输入框 → 物理点击聚焦 → 输入 text | 同上，target_desc 用自然语言 |

底层还有 `web_scan`（读页面文本/结构）和 `web_execute_js`（执行 JS、改地址、读 `__INITIAL_STATE__`），用于**读数据**和精确控制。

### macOS 现有 Chrome 无桥操作

`web_desktop(action=snapshot)` 读取正常辅助功能树，返回 `snapshot_id` 与节点 `ref`、
文字、输入值、坐标及浏览器标签。已验证本机小红书主页与创作中心可读。
`press(ref,snapshot_id)` 优先 AXPress，必要时按 AX 实测坐标进行普通点击；
`fill(ref,snapshot_id,text)` 仅替换文本输入；`key` 支持 Enter/Tab/Escape、
地址栏和文件对话框“前往文件夹”等快捷键。此通路不注入 JS，不修改浏览器策略。

动作成功仅表示输入已发送，必须重新 snapshot 核对业务结果。引用在每次动作后失效，
重新观察后再动手。不要把 1×1 的隐藏占位节点当可见控件，不进入密码输入。
CDP 专用工具仍需桥；桌面证据不能冒充 CDP 成功。

`hover`按新鲜AX引用悬停，等tooltip文字识别无标签图标，再重新snapshot点击；
不按“第几个图标”猜动作。snapshot还包含独立系统对话框和focused_element；
Chrome地址栏自动建议会接管AX焦点，不能仅用文本框AXFocused判导航失败。
编辑页离开确认仅在内容完整回读与之前一致时通过，其他未保存内容先保留。

## 标准操作循环（像人一样点一个东西）

```
1. 先看清楚：进新页/不确定布局 → web_learn_page() 认一遍页面（或 web_scan 读文本）
2. 想清楚要点什么：用自然语言描述目标 target_desc
3. 动手：web_visual_click(target_desc) / web_visual_fill(target_desc, text)
4. 验证反应：看返回的 verified / 再 web_scan 或 learn_page 确认"页面真的变成了预期的样子"
       └─ 没反应 / 变错了 → 换个 target_desc 描述、或先滚动让目标进入视野、或重新 learn_page
5. 成功 → 引擎已自动把该元素的 selector 结晶进缓存，下次免 VLM 秒点
```

## 自学习 / 结晶机制（为什么"越用越快"）

引擎内置三级降级（`tools/web_vision.py`），对应"第一次靠看、之后靠记忆"：

```
第一次操作某元素：
  查缓存 miss → 给页面元素编号(Set-of-Marks) → VLM 做"选择题"选中目标 → 物理点击
       → 点击前后抓页面指纹对比，确认"真的有反应"(verified)
       → 验证通过 → 反查出稳定 CSS selector 写入 .cache/web_locator_cache.json   ← 结晶(L1)
第二次操作同一元素：
  查缓存 hit → 校验 selector 还在 → 直接 CDP 点坐标，零 VLM                      ← 秒杀
       → selector 失效(平台改版) → 失败计数++，超阈值自动删除 → 退回视觉重新学    ← 自愈
```

要点：
- **不要怕第一次慢**——第一次是"看着学"，学会就快了。
- **Set-of-Marks 选择题**比"让 VLM 直接报坐标"准得多，能有效防点偏。
- **点击前后指纹对比**能抓出"点了没反应却以为成功"的假信号（看 `verified` 字段）。

## 什么时候走这里 vs 走专用工具

| 场景 | 怎么做 |
|---|---|
| 平台有专用工具且没失败（如小红书读 `__INITIAL_STATE__` 抓正文/评论） | **优先专用工具**（快、省、提数准） |
| 平台没有任何专用工具（B站等网站的按钮操作） | **直接走本引擎**，像人一样看着操作 |

抖音浏览/搜索已有 `douyin_browse` 专用能力，优先读取对应SOP并调用。
登录验证或平台限制不能通过通用引擎绕过。
| 专用工具失败（改版/token错配/selector 找不到/被风控页拦） | **降级到本引擎**重试，别直接报错放弃 |
| 需要"操作"（点赞/关注/发布/导航/点开某项） | 本引擎是主场 |
| 需要"批量精确提数"（几十条的正文/评论/点赞数） | 有读数据工具优先用；没有才用 `web_scan` 逐页读 |

> 经验法则：**"操作"默认走视觉自举，"批量提数"优先走结构化读取。** 视觉擅长动手，不擅长精确抄数。

## 沉淀（结晶到更高层）

- **L1（自动）**：元素 selector，引擎自己写缓存，无需你管。
- **L2（任务证据）**：在某平台跑通流程后，把有效操作序列记录到当前任务。
- **L3（值得时做）**：某流程高频又稳定 → 用 `create_skill` 沉淀方法，或由开发者实现专用工具。

## 纪律
1. 进陌生页先 `web_learn_page` 看一遍，别盲点。
2. target_desc 用清晰自然语言，点完**必须验证**反应（`verified` / 再 scan 一次）。
3. 失败先换描述/滚动/重学，**3 次仍不行**才求助用户（RULES 第4条）。
4. 写操作按用户已有授权和上层 SOP 执行；本项目用户已授权账号实测和发布，不重复询问。
   花钱、账号注销等未授权操作需明确指令；验证码和安全校验不绕过。
5. 跑通新流程后主动沉淀 L2，别让经验只停在缓存里。
