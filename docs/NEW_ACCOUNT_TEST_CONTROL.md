# 账号绑定、共享额度与测试接续

这是应用执行规则。具体账号身份、风险原文、测试残留与个人授权留在本机，不随源码分发。

## 默认行为

- `tools/xhs_test_control.py` 统一管理写操作预算，`tasks/test_control.json` 保存绑定与领取历史，跨线程/进程加锁，原子替换落盘。
- 默认测试控制开启、账号未绑定、后台队列暂停。使用 `xhs_test_account` 的 status/bind/pause 管理状态；工具不提供降低限制或开启后台的参数。
- 工程上限：全局提交间隔至少30分钟；单账号滚动24小时最多4次提交，其中 publish 最多1次。发布、保存、修改、删除、互动、评论、私信、合集与 RSS 共用预算。
- 额度不是平台官方安全阈值，不能保证避免账号限制。失败、超时与未知结果仍保留领取记录，重启不清零。

## 身份与归属

绑定需要真实主站“我”链接、健康自己的主页、稳定 ID 和创作中心身份相互匹配。有未完成编辑器或合集表单时保留页面并拒绝绑定。昵称不是唯一身份。

新账号健康观察不会覆盖旧账号限制。损坏记录不能被一次观察自动清除；只有同一账号的健康主页证据才能恢复该账号。这里不保存密码、Cookie 或验证码。

旧任务不自动迁移；浏览器本地草稿以类型、标题与保存时间识别，不能凭新昵称判断归属。测试模式停止旧草稿的 publish/delete，读取仍可用。

## 提交与恢复

准备前核对额度和主站 ID，提交前再次核对主站与创作中心；在操作 journal 前原子领取预算。已存在相同 journal 时只读返回，已领取但缺 journal 的中断操作也不能再次领取。

额度不足返回 `deferred`、`submitted=false`、原因与 `retry_after`，结束当前轮，不睡眠等额度。保存草稿与创建合集是各自独立的提交，必须分阶段接续。

队列默认不检查或切换浏览器。手动 `run_due` 核对到期、身份与预算，拒绝时保留 queued/attempts=0。running/uncertain 通过只读 reconcile 核对，禁止自动重发。队列发布规格必须包含 owner_id 与 expected_account。

RSS 确认需真实选中合集与 feed、邮箱、起始时间一致；同名菜单项不构成字段已选证据。

## 真实验收顺序

1. 在平台正常登录，先只读核对健康主页与创作中心，再按当前实例授权绑定。
2. 使用独立任务与明确用途的素材，优先读取现有内容，避免重复提交。
3. 到达额度记录下一次可执行时间，保留已完成证据；不以重发验证成功。
4. RSS 最终导入需要真实 feed、邮箱、已有合集和平台验证码；私信发送需要获得授权的接收对象。
5. 缺权限返回真实状态，不补零、不申请权限、不把表单成功当服务端完成。

上述闸门约束应用工具，不是操作系统沙箱。通用代码执行也必须遵守实例授权与平台限制。功能证据范围见[能力矩阵](CAPABILITY_MATRIX.md)，安装步骤见[安装说明](installation_zh.md)。
